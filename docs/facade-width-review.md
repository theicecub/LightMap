# Ширина фасадов: данные на проверку

`width` (метры) — протяжённость остеклённой плоскости вдоль улицы. В модели она
задаёт **длину опасного участка дороги**: у 200-метровой «пластины» блик тянется
втрое дольше, чем у башни. Сейчас поля нет ни у одного из 33 зданий, поэтому
подставляется типовое `DEFAULT_FACADE_WIDTH_M = 60`; при загрузке об этом пишет
предупреждение в консоль (`auditFacadeWidths` в `script.js`).

## Откуда числа

Overpass API, контуры зданий OpenStreetMap (ODbL), запрос вида
`way(around:30,<lat>,<lon>)["building"]`, срез от 2026-09-05. Берётся охватывающий
прямоугольник контура и проецируется на линию фасада (перпендикуляр к `orientation`):

```
W = W_вз · |cos θ| + W_сю · |sin θ|,   θ = orientation
```

> **Это оценка сверху.** Контур вписан в прямоугольник, значит истинная ширина не
> больше приведённой. Для комплексов из нескольких башен прямоугольник накрывает их
> все сразу. Поэтому значения **намеренно не внесены** в `buildings.json`:
> завышенная ширина растягивает опасный участок маршрута и даёт ложные тревоги.

## Что делать

1. Проверить строки с достоверностью «высокая» по спутниковому снимку и внести `width`.
2. Для комплексов («Северное Сияние», «Триумф», «Изумрудный квартал») указывать ширину
   ОДНОЙ башни, обращённой к дороге, а не всего квартала.
3. Всенаправленным объектам (Байтерек, Нур Алем, Пирамида, «Шабыт») ширина не нужна —
   у них нет плоскости остекления, работает `computeOmniGlare`.
4. Как только у здания появится `width`, оно исчезнет из предупреждения `auditFacadeWidths`.
